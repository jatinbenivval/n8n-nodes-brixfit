# v1.3.0 — 2026-05-31

## New Features

### Brixfit Trigger: Automatic webhook registration

Previously you had to manually copy the n8n webhook URL into the Brixfit dashboard and paste the secret back. Now it's fully automatic:

- **Activate** the workflow → the node calls `POST /api/public/v1/webhooks`, registers itself, and stores the signing secret internally
- **Deactivate** the workflow → the node calls `DELETE /api/public/v1/webhooks/:id` and cleans up automatically

The "Webhook Secret" field still exists as an optional manual override for users who created a webhook outside n8n and want to reuse its secret. For everyone else, leave it blank.

### Lead / Client: Get Health Report (latest)

New operation on both Lead and Client resources. Fetches the most recent AI-generated health report for a record, including:

- The full `report` object (narrative + recommendations)
- `metrics` — computed values gated to your Brixfit plan (BMI, BMR, TDEE, body fat %)
- `pdf` — download URL for the latest non-expired PDF (if generated)

### Lead / Client: List Health Reports

New paginated operation that returns all AI health reports for a lead or client (newest first). Supports `page` and `per_page` parameters. Each record includes the report content, creation date, and attached PDF metadata. Plan-gated metrics are returned in `meta.metrics`.

### Plan-gated metrics on Lead Create

The Create Lead response now includes a `health_metrics` field populated with computed body metrics (BMI, BMR, TDEE, body fat %) — but only the metrics your Brixfit plan allows. Coaches on basic plans see only BMI; higher plans unlock BMR, TDEE, body fat %, etc.

### Return All auto-pagination

Lead, Client, and Check-in **Get All** operations now have a **Return All** toggle. When enabled, the node automatically loops through every page using the `total_pages` value from the API response and merges all records into a single output. When disabled, a manual `Limit` field controls the page size (default 20).

### Dynamic lead statuses

**Update Status** on the Lead resource now loads your custom pipeline stages from Brixfit in real time via `GET /api/public/v1/leads/statuses`. The dropdown always reflects your current setup — no hardcoded values, no stale options.

## Bug Fixes

### Sort parameter format mismatch

Sort option values were sent as `created_desc`, `name_asc`, etc. but the API parses them as `created_at:desc`, `name:asc` (colon-separated). All sort options now use the correct format. Two new sort options are also added: **Updated — Newest First** and **Updated — Oldest First**.

### SSRF in dynamic field loader

`loadLeadFieldsFromApi` was constructing the API URL as `` `${credentials.baseUrl}/api/public/v1` `` — bypassing `validateBaseUrl` entirely. The credential's base URL was not checked for private/internal network addresses before being used. Fixed.

### Check-in status was a free-text field

The **Status** filter on Check-in Get All was a `string` input, meaning users could type anything and send it to the API. It is now a proper `options` dropdown with the four valid values: `completed`, `overdue`, `pending`, `reviewed`.

### `NodeConnectionTypes` import

Both nodes were importing from a non-existent `NodeConnectionType` (singular). The correct export in `n8n-workflow` is `NodeConnectionTypes` (plural). All `inputs`/`outputs` declarations now use `NodeConnectionTypes.Main`.

## Improvements

### Codex metadata on both nodes

Both `Brixfit` and `BrixfitTrigger` now declare full codex metadata — categories (`CRM`), subcategories (`Fitness & Coaching`), aliases, and links to primary and credential documentation. This makes the nodes discoverable in the n8n node search and appears correctly in the community node list.

### `usableAsTool` on the action node

The **Brixfit** action node now declares `usableAsTool: true`, making it available as a tool inside n8n AI Agent workflows. You can now use Claude, GPT, or other AI agents to query and update Brixfit data conversationally.

### `engines` field added to package.json

`"engines": { "node": ">=18.0.0", "n8n": ">=1.0.0" }` is now declared, so npm warns users on incompatible Node.js or n8n versions before install.

### SVG icon always included in build

The build script now copies `brixfit.svg` to `dist/nodes/Brixfit/` automatically (`tsc && cp ...`). Previously the icon was listed in `files` in `package.json` but not guaranteed to land next to the compiled JS, which could cause icon-not-found errors in some n8n setups.

### Webhook URL HTTPS enforcement (Webhook Create)

The Webhook → Create operation now checks that the URL begins with `https://` before calling the API and surfaces a clear error if it doesn't — consistent with the server-side validation.

### Email sort options

Lead Get All and Client Get All now include **Email A–Z** and **Email Z–A** as sort choices.

### Shared utilities module

`validateBaseUrl`, `validateId`, `REQUEST_TIMEOUT_MS`, and `WEBHOOK_EVENTS` are now in a shared `Brixfit.utils.ts` module imported by both nodes. This ensures both the action node and the trigger node get identical SSRF and path-traversal protection.

## Backend Changes (BrixFit API)

These changes are in the main BrixFit project and are required for the new n8n operations to work:

| Endpoint | Change |
|----------|--------|
| `GET /api/public/v1/leads/statuses` | **New** — returns coach's custom pipeline stages, used by the dynamic status dropdown |
| `GET /api/public/v1/leads/:id/health-report` | **New** — latest AI health report + plan-gated metrics + PDF for a lead |
| `GET /api/public/v1/leads/:id/health-reports` | **New** — paginated list of all health reports for a lead |
| `GET /api/public/v1/clients/:id/health-report` | **New** — latest AI health report + plan-gated metrics + PDF for a client |
| `GET /api/public/v1/clients/:id/health-reports` | **New** — paginated list of all health reports for a client |
| `POST /api/public/v1/leads` | **Updated** — response now includes `health_metrics` filtered by coach plan |
