# v1.5.0 — 2026-10-05

Check-ins now come with the client's name and the full questions and answers. Errors say what actually went wrong.

## New

- **Check-in answers.** Check-in → Get Many, Get by Client and Client → Get Check-ins return `client_name`, `client_email`, `answers` (each question, its type, unit and the answer given) and `answers_text` (a ready-to-read summary, handy for AI agents and emails). Turn **Include Answers** off for a lighter, faster list.
- **Check-in → Get.** Fetch one check-in by ID with every question and answer.
- **Find check-ins by client name or email** with the new **Client Name or Email** filter.
- **Check-in Submitted trigger** now carries `client_name`, `answers` and `answers_text`, so no follow-up call is needed.

- **Pick people by name.** Client and Lead fields are now dropdowns of names (your newest 500 clients and leads). You can still switch to an expression and use any ID, and saved workflows keep working.
- **Date pickers** for check-in From/To dates.
- **Ready-made workflows** in the `workflows/` folder. Import one into n8n, choose your credentials and activate:
  1. Welcome every new lead by email
  2. Email me every submitted check-in, with all questions and answers
  3. Daily list of overdue check-ins
  4. Weekly list of check-ins waiting for your review

## Fixed

- **Status "Reviewed" failed with a vague error.** Statuses now match what Brixfit stores: Completed, Needs Review, Reviewed, Pending, Escalated, Scheduled, Overdue, Missed and Excused. Invalid values get a clear message listing the allowed ones.
- **Unclear errors.** The node now reads Brixfit's own message from n8n's wrapped errors, instead of showing only "Bad request - please check your parameters". Connection failures and server errors also explain the next step.
