# v1.3.1 — 2026-05-31

## Brixfit Trigger — 6 improvements

### 1. Auto-registration notice in the UI

The node now shows a clear info banner explaining that the webhook secret is managed automatically. When you activate the workflow, n8n registers a signed webhook in your Brixfit account and stores the secret securely. Deactivating removes it. No manual copy-paste required.

### 2. `client.deleted` event added

`client.deleted` was dispatched by the Brixfit server but was missing from both the node's event dropdown and the API's validation list. Both are now fixed — you can subscribe to client deletions.

### 3. Events auto-sync on reactivation

Previously, if you changed the event selection after the workflow was already active, the registered Brixfit webhook still had the old events. Now `checkExists` compares the stored event fingerprint against the current selection — if they differ, it returns `false`, triggering an automatic delete + re-register with the correct events.

### 4. Flat output — `$json.name` instead of `$json.data.name`

Brixfit payloads wrap the record inside a `data` key:
```json
{ "event": "lead.created", "timestamp": "...", "coach_id": "...", "data": { "name": "John" } }
```
The node now flattens `data` to the top level. Downstream expressions use `$json.name`, `$json.email`, `$json.id` directly. Meta fields are accessible as `$json._event`, `$json._timestamp`, `$json._coach_id`.

### 5. Options panel (replaces scattered fields)

Three new options are now grouped in a collapsible **Options** panel:

| Option | Default | Description |
|--------|---------|-------------|
| **Require Valid Signature** | `true` | Rejects requests with a missing or invalid HMAC-SHA256 signature. Disable only for local testing. |
| **Replay Protection Window** | `5 min` | Rejects signed requests whose `X-Brixfit-Timestamp` is older than N minutes. Prevents replayed payloads. Set to 0 to disable. |
| **Webhook Description** | *(blank)* | Label shown in Brixfit → Developer → Webhooks so you can identify which n8n workflow owns each registration. |
| **Manual Webhook Secret** | *(blank)* | Override for users who created a Brixfit webhook manually outside n8n. Leave blank for auto-registration. |

### 6. Replay attack protection

After a valid signature passes, the node checks `X-Brixfit-Timestamp`. If the timestamp is missing, unparseable, or older than the configured window (default 5 min), the request is rejected with HTTP 401. This prevents an attacker who captured a valid signed payload from replaying it later.

## Backend change (BrixFit API)

`client.deleted` added to `VALID_EVENTS` in `src/app/api/public/v1/webhooks/route.ts`. Previously the dispatch system fired this event but the registration API rejected it with a 422.
