# v1.4.1 — 2026-10-05

Works with Brixfit's new API key permissions, avoids duplicate leads on retries, and gives clearer errors. Existing workflows keep working with no changes.

> Works with the current Brixfit and with the upcoming security update. The new behaviours below switch on by themselves once your Brixfit account has the update.

## New

- **API key permissions.** Brixfit keys can now be limited to what a workflow needs — Read-only, Lead capture or Full access. The credential test accepts any valid key, whatever its permissions.
- **No duplicate leads on retry.** Lead → Create and Webhook → Create send an idempotency key. If n8n retries the node, Brixfit returns the first result instead of creating a second lead.
- **Automatic wait on rate limits.** When Brixfit asks the node to slow down, it waits the requested time and retries (up to twice, for waits of 30 seconds or less) before reporting an error.
- **Stronger trigger verification.** The Brixfit Trigger checks the new timestamped signature when Brixfit sends it, so a captured delivery cannot be replayed later. Deliveries from older Brixfit versions are verified as before.

## Improved

- **Clearer errors.** The node now tells you when a key has expired, has been retired, lacks a permission (and which one it needs), or when the plan does not include API access.
- **Continue On Fail output** now carries the same readable message as a normal failure, plus a `hint` field with the suggested fix.

## Good to know

- The Brixfit Trigger registers and removes its own webhook, so its key needs the **Full access** preset (or the `webhooks:manage` permission).
- Brixfit may now deliver the same event more than once if your n8n instance was briefly unreachable. A repeat carries the same `_event`, `_timestamp` and record `id`, so you can skip it where that matters.
